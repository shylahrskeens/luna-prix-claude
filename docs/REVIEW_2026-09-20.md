## BLOCKER

### B0 — Most of the field is now listed DNF on Ruin
`src/sim/race.ts:281-289` — `this.finishRacer(r, true, projected)`

Closing B4 flipped `timedOut` from `false` to `true` for every racer still running when
the finish window shuts. `finishRacer` sets `p.dnf` from that flag, and the player's own
tail is only 4 s (`race.ts:428`), so anyone more than four seconds back is never credited.
The `hardStop` guard added at 12:45 protects the *player*; it does nothing for the field.

**`npm run check`, run at 12:48 against the current tree — it passes, but:**

```
ruin seed 11  skip@0.5s  dnf 7   1:YOU 2:Brambl(DNF) 3:Marrow(DNF) ... 8:Tumble(DNF)
ruin seed 23  tail runs  dnf 4   1:Marrow 2:Tumble 3:Kestre 4:YOU 5:Brambl(DNF) ...
ruin seed  3  tail runs  dnf 3
```

At 12:35, before the change, all 18 rows read `dnf 0`.

**What a judge sees:** win on Ruin and the results table says nobody else finished — seven
rows of `DNF` and `—` for time (`src/ui/screens.ts:626`). That reads as broken, not as
authoritative. `race.ts`'s own comment at `:279` makes the point: *"Marking them DNF would
hand the player every place behind them, which is a lie."*

**Fix (smallest):** DNF only racers who genuinely did not cover the distance, and keep the
projected time for the rest —
`this.finishRacer(r, r.progress.raw < this.cfg.laps - 0.5, projected);` — or raise the
player's tail from 4 s so the field actually lands. Re-run `check:finish` either way.

## SHOULD-FIX — still open at 12:46

**S1 — Mega Ramp and Luna Launch have no time limit once `launched` is set.**
`src/game/bonusRun.ts:129-131` and `:196`. The only timeout is
`if (core.time > this.def.timeLimit && !this.launched)`. After `launched`, Mega Ramp can
only end through `else if (this.phase === 'flight')` (`:126`), which needs an airborne
`update()` *after* the frame that set `launched`, then a grounded one. If `launched` is
ever set on a frame followed directly by a grounded frame, `phase` stays `'run'`, no
branch matches, the timeout no longer applies, and the only exit is Escape → Quit.
**I did not reproduce this** — the drift hop is ~0.3 s — but there is no backstop.
*Fix:* move the `core.time > timeLimit` check out of the `!launched` branch in both.

**S2 — Key rebinding has no cancel and no duplicate check.** `src/ui/screens.ts:1049-1069`.
Clicking a row installs a capturing `keydown` listener removed only by the *next*
keypress — navigate away and it stays armed, silently binding whatever is pressed next.
Nothing stops two actions sharing a code: bind `pause` to `KeyW` and W both accelerates
and pauses. *Fix:* remove on blur too, and reject a code already in use.

**S3 — A bonus run permanently restyles the shared race HUD.** `src/ui/hud.ts:296-303`.
`toastLive` writes `posEl.style.fontSize = '34px'` and `lapEl.style.fontSize/color` inline
and nothing restores them. `Hud` is built once (`main.ts:64`) and reused, so after any
bonus event the position and lap readouts stay at bonus sizing for the rest of the
session. *Fix:* clear those three inline styles in `Hud.prepare()`.

**S4 — "Erase profile" does not erase, and can resurrect an old save.**
`src/ui/screens.ts:1150-1153` vs `src/persist/store.ts:200-228`. It hardcodes
`localStorage.removeItem('lunaprix.profile.v3')` instead of calling `resetProfile()`, and
clears neither `LEGACY_KEYS` (`store.ts:16`) nor `lunaprix.server`. `loadProfile` falls
back to the legacy keys, so on a machine with a v1/v2 save the erase is undone on the next
load — under a dialog reading "This cannot be undone." It is also outside any `try`, so it
throws where storage is blocked and `location.reload()` never runs.

**S5 — No WebGL context-loss handling.** `src/main.ts:672-686`, `src/render/scene.ts:209`.
`boot()` tests for WebGL once; `grep -rn "contextlost" src/` returns nothing. A laptop
waking from sleep drops the context and every `ctx.render()` throws thereafter.

**S6 — A finished kart can fall out of the world during the tail.**
`src/sim/kart.ts:601-604` calls `triggerRespawn()` when a finished kart is over a gap, but
`triggerRespawn` returns immediately for `mode === 'finished'` (`:662`), so it falls
forever — on camera, during the post-race cinematic.

## Honesty gaps — claim vs code

Each one below I traced to the line myself.

**H1 — "Bots have no hidden speed and no dynamic difficulty." BLOCKER.**
`docs/COMPLIANCE.md:75-77`, repeated in `src/sim/ai.ts:4`. Both halves are false outside
ranked. Hidden speed: `race.ts:639-652` sets `kart.catchUp = 1 + behind * strength * 0.16`
**for bots only** (`:648` forces `1` for everyone else), and `kart.ts:450` multiplies
`topSpeed` by it while `:457` multiplies accel. Quick Race runs `catchUp: 0.35`
(`rules.ts:34`). Dynamic difficulty: `main.ts:366` derives `difficulty` from the player's
rating (0.80→1.15) and `ai.ts:91` folds it into bot skill. The bullet two lines above
already concedes "Ranked … sets catch-up to zero", so the doc contradicts itself.
*Fix:* say "outside ranked, trailing bots get up to 5.6% catch-up and the field's skill
scales with your division" — which is a better story than the false absolute.

**H2 — "The server … owns finish order and the published result … it exists now."
BLOCKER.** `docs/SUBMISSION.md:83-88`, `docs/ARCHITECTURE.md:94-95`. `submitResult` is
declared three times (`net/ws.ts:222`, `net/local.ts:64`, `net/adapter.ts:84`) and has
**zero callers** in `src/`. `main.ts:449` builds the result from `view.core.buildResult()`
— the local sim — for server races too, and that is what awards coins, rating and records.
The server really does compute and send an authoritative result
(`server/index.mjs:239-265`), but only `tools/netclient.mjs` ever reads one.
*Fix:* either call `submitResult` in `finishRace` when `view.net` is set, or reword to
"the server validates and publishes; the client currently displays its own prediction".

**H3 — "A result carrying an integrity flag is held back rather than published, both
offline and on the server." SHOULD-FIX.** `docs/COMPLIANCE.md:78-79`, shown to the player
at `src/ui/screens.ts:588`. Offline it is false: `main.ts:472` calls `submitRecord`
unconditionally, outside the `me.integrity.length === 0` guard on `:464`, and
`store.ts:245` never inspects integrity. Only the *rating* is withheld; the records board
is not.

**H4 — Screenshots that do not exist. SHOULD-FIX.** `docs/SUBMISSION.md:141` promises
"the Ruin temple gate, results, and the phone layout". `docs/evidence/screens/` holds five
files: gator-pit ×2, mega-ramp result, garage, cloudforge. None of the three named. The
path in the doc is also wrong (`docs/evidence/`, not `docs/evidence/screens/`).

**H5 — `npm test` is a hollow script. SHOULD-FIX.** `package.json` declares
`"test": "node --test test/*.test.mjs"`; there is no `test/` directory. No doc claims
coverage, but a judge who types it gets a silent zero. Point it at `npm run check`.

**H6 — "two bonus events" — there are three. SHOULD-FIX.** `index.html:7` and
`src/ui/screens.ts:154`; the home button (`:160`) names only "Mega Ramp and Gator
Gauntlet". `src/data/bonus.ts:339-390` ships Luna Launch too, and
`bonusSelectScreen` renders all three — so a judge finds an event no copy mentions.
README and SUBMISSION.md were corrected at 12:41; these two were not.

**Checked and sound:** no third-party assets ship (`assets-incoming/` is gitignored, no
`.glb`/loader reference anywhere in `src/`); the 728 KB / ~201 KB-gzipped figure matches
`dist/` byte for byte; the three Axies carry `source: 'mock-local'`; there is no chain,
wallet or indexer code; the geometry validator and the 21-race harness are real and pass.
